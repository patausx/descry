# BUGS — найденное в descry (2026-08)

## B1. рассинхрон Song-треков — ИСПРАВЛЕН В ДВИЖКЕ

Раньше каждый трек самостоятельно вызывал переход на следующую Song-строку, когда заканчивался его чейн. Из-за этого короткий чейн и `EMPTY`-ячейка убегали вперёд относительно длинного чейна.

Теперь Song-строка — **общий временной контейнер для всех восьми треков**. Её длительность равна самому длинному чейну в этой строке (с учётом `Phrase::length`, минимум одна 16-шаговая фраза). Короткий чейн повторяется внутри этой строки, `EMPTY` молчит, а следующая строка включается одновременно на всех треках. `song_wrapped()` тоже выставляется только общей границей, поэтому пустые неиспользуемые треки больше не обрезают offline render.

Регрессия закреплена `tools/test_song_sync.cpp`. Старые сломанные демо-генераторы удалены; поддерживается один релизный демо-трек — IRONLUNG.

## B2. фантомный `granular.cpp` — ИСПРАВЛЕН

Файлы гранулятора были удалены раньше; устаревшие записи убраны из project map, а host-команда использует актуальные `core/synth/*.cpp`.

## B3. `.tr3d` не содержит аудио — сэмплерные демо молча немые

`SamplerParams.sample_slot` — индекс в глобальный `SampleBank`, наполняемый отдельными `sample_XX.s16`.
Проект с сэмплерным инструментом, приехавший без `.s16`, играет тишину на этих треках **без единого предупреждения**.
Прямо влияет на возврат демо-пака в релиз: класть только `.tr3d` недостаточно.
**Фикс:** демо-пак = `project_XX.tr3d` + все нужные `sample_XX.s16` + `.name`.

## B4. нумерация слотов разъезжается: проекты hex, сэмплы dec

```
project_%02X.tr3d   // 00..0F ШЕСТНАДЦАТЕРИЧНО
sample_%02d.s16     // 00..63 ДЕСЯТИЧНО
```
В одной директории. Для слотов 0..9 совпадает, дальше — грабли: слот 10 это `project_0A.tr3d`, но `sample_10.s16`.
Не баг движка (обе стороны последовательны), но гарантированная ловушка для скриптов и для человека. Задокументировано в `docs/ENGINE_NOTES.md`.

## B6. sample slot 32 конфликтовал с IRONLUNG — ИСПРАВЛЕН

IRONLUNG использует зарезервированный релизный слот `63`. BMT add-on переименован в `tools/build_bmt_3ds_slots_32_62.py` и создаёт только слоты 32–62. Curated pack остаётся в 00–31, так что диапазоны больше не пересекаются.

## B7. `make demo` первоначально ошибочно требовал devkitARM

Новый таргет был добавлен ниже host-only секции, но `HOST_ONLY_GOALS` содержал только `tests`. На машине без devkitARM `make demo` падал до запуска host-компилятора. Исправлено добавлением `demo` в `HOST_ONLY_GOALS`.

## B8. документация генератора ссылалась на удалённый `granular.cpp`

Первая версия команды в `docs/ENGINE_NOTES.md` включала несуществующий `core/synth/granular.cpp`, поэтому copy-paste сборка падала. Это следствие фантома B2. Исправлено: команда теперь использует актуальные `core/synth/*.cpp` без упоминания удалённого файла.

## B9. upload-диагностика путала смену сети с неверным IP

Во время первой попытки компьютер был `192.168.0.137/24`, поэтому `192.168.1.105` был недостижим. Позже компьютер переподключился как `192.168.1.107/24`; 3DS по `.105` стала отвечать на ping, но `tcp/5000` возвращает `connection refused` — консоль жива, ftpd не запущен. Это не баг descry, но скрипт заливки теперь сначала probe-ит FTP и выдаёт явную ошибку вместо зависания.

## B10. upload-скрипт добавлен в рабочий набор

`tools/upload_3ds.sh` проверяет наличие всего комплекта IRONLUNG (`project_00.tr3d`, `sample_63.s16`, `sample_63.name`) и кладёт бинарь в установленный путь `/3ds/descry/descry.3dsx`.

## B11. первая версия upload-скрипта клала `.3dsx` не туда

README требует `/3ds/descry/descry.3dsx`, а первая версия `tools/upload_3ds.sh` отправляла бинарь в `/3ds/descry.3dsx`. Это создало бы второй launcher-entry в корне `/3ds` вместо обновления установленной копии в её папке; пользователь мог бы продолжить запускать старую версию. Исправлено до первой успешной заливки.

## B5. `Song::dly_time` хранится квантами по 32 фрейма

Движок явно конвертирует значение в `dly_time * 32` фреймов. При фиксированном аудиотракте 32 кГц один квант равен 1 мс; mixer UI теперь показывает `DTIM` с суффиксом `ms`, а engine notes фиксируют настоящий контракт хранения.
